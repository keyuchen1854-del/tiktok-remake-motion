# 本项目视频制作流程

**本项目唯一的视频生成技能是 [$tiktok-sales-video-remake（带货出单复刻）](.agents/skills/tiktok-sales-video-remake/SKILL.md)。** 它涵盖出单策划和完整版复刻，内部用 $video-reverse 拆原片。该入口适用于本项目新对话和续作，优先于通用选路和其他对话的默认路线。Gem 完整版、轻量版及其他生成工作流在各自项目执行。

**新对话先读规则，再确认改动。** 收到复刻原片（附件、路径或链接），先读取本文件和带货出单复刻的 `SKILL.md`。如果用户只给原片，或只说做样片、试跑流程、看复刻效果但还没说要改什么，先问「这条视频的人物、发型、服装和背景想换成什么？哪些按原片保留？」等用户答复后再打开或处理原片。用户一次给齐原片和明确的修改需求，或明确说按原片复刻，沿用本项目流程和模型时直接开工。明确只改一项时，其余按原片保留。同一条视频续作沿用已确认的要求，新改动按当次指示。需下载或安装时，先说明对象和用途并取得明确授权。

- **复刻制作顺序。** 核对商品与出单目标 → $video-reverse 拆原片 → 完整版 43 列逐镜改写及中英文动作提示词 → 内置图片模型先出一张基准单图，再逐张生成及检查单图，拼出完整编号宫格 → 用户确认宫格 → Capsule 校验单图、对应静音原片段及提示词 → 在本批授权范围内提交一次 H3 代表段 → 代表段验收通过后提交其余段落、验收和回拼。
- **视频复刻关键帧补图。** 内置图片模型遇到普通故障、超时或出图不合格时，先定位问题，再用内置模型补做对应失败单图一次。连续两次失败则停止同类重试并诊断。内置图片模型明确返回安全审核拒绝时，记录拦截结果，核对目标画面、提示词和参考图。确认该帧内容符合适用规则后，按既有授权直接用本机 Qwen-Image-Edit-2511 对对应单图整图补一次。补图核对商品、动作和人物一致性，通过后放回对应编号。已通过的单图继续使用。
- **只换背景**且原片商品、手和动作均符合交付要求时，优先评估保留前景的遮罩合成。核对边缘、手和商品遮挡，以及字幕和原声时序。涉及重新生成视频片段时按本项目完整版执行。
- 使用 [视频复刻工具说明](../tools/video-remake/README.md) 中的分段清单。保留源音轨与时码，记录输入版本、H3 任务 ID 和片段验收结果。素材准备、提交、验收与回拼分别记录。回拼并验收后执行下方的视频交付前自动检查。

## 商品策划和发布后复盘

收到「用出单流程做这个」时，使用同一技能的商品取证、选题、脚本或复盘步骤。已有指定复刻原片时，在同一技能里顺接完整版；只有商品资料时先交策划与可拍分镜，生成复刻需要原片和改动要求。

## 指定人物

使用指定人物时，用本次授权的参考图作为人物档案，结合原片动作帧对照人物、商品结构和穿戴状态。人物参考、背景或口播缺失且影响下一步时补问。

## 关键帧出图自检

- **先锁商品和构图。** 用原图及已有实拍核对对应角度、件数、穿戴状态、结构和花纹。换人同时保商品时，提示词写清机位、景别、肩线、领口、下围和手部接触位置。文胸按画面可见项核对罩杯、肩带、下围、后扣及单穿或叠穿层次。
- **先检查生成图再合成。** 先出一张代表帧，用同一裁切和尺寸对照生成图、原图与蒙版，检查商品轮廓、肩线和手部遮挡。人物站位、体型、姿势或视角变化导致商品错位时，先修正构图或参考，禁止把原商品像素直接叠到错位的新人体上。原始生成图已出现结构错误时，退回生成环节。
- **结构过关才标为基准图。** 实际查看全图和商品局部。多一组罩杯、重复肩带或后扣、错层和穿模都判失败，禁止进入宫格、图生视频或批量生成。记录具体差异及首次出现的环节，按本项目原有重试范围修正后复验。

## 视频复刻长期验收规则

- **产品严格保持一致。** 对照原片及已确认的实拍图，核对款式、结构、颜色与花纹、比例、可见细节和使用方式。商品在任一时刻出现变形、结构增减或款式变化，该片段即不通过，须定位问题时间点。
- **产品不一致时，针对问题片段重生成一次。** 在已授权的生成和费用范围内，先按问题修正提示词或参考帧，再重生成一次。复验仍不一致时，停止继续重试，向用户报告片段、时间点及具体差异，等用户补充实拍图后再返修。已有能说明该差异的实拍图时直接复用。
- **轻微画面瑕疵的容许范围。** 代表段和后续各段中，开头或收尾构图比原片略宽、人物或背景有轻微瑕疵等情况，单处持续不超过 3 秒，且不影响用户明确提出的需求点和产品一致性时，默认可以接受。人物身份、场景设定和画面连贯性仍须符合任务要求。

## 视频交付默认在对话内预览

### 视频交付前自动检查

交付成片、代表段、审看版或对比视频前，从项目根目录对要交付的每个最终文件运行同一脚本。视频路径用实际交付路径，预览目录用当前对话有写权限的持久目录，优先使用本对话的可视化目录。确认输出的文件链接指向本次验收的版本。若改了导出路径或重新回拼，交付前用新文件再检查一次。

```powershell
python .\tools\check_video_delivery.py --video "<实际交付视频的绝对路径>" --preview-dir "<本对话可用的预览目录绝对路径>"
```

- `file_invalid`：文件缺失、为空或无法识别为可用视频。先核对现有交付路径或回拼结果，修正后重跑。未通过时不发失效链接或称已交付。
- `preview_verified`：文件通过检查，预览已在隔离的后台测试中验证默认暂停、显示播放控件、点击后进度推进。把输出的 `preview_embed` 原样单独放在当前对话的交付消息中，并附上 `file_link`。普通 MP4 链接和 Markdown 图片写法不算通过预览检查。后台测试验证的是待嵌入播放器，实际客户端显示以交付消息为准。
- `preview_unavailable`：文件通过检查，但无法生成或验证可点播预览。交付消息说明脚本返回的具体原因，并附上 `file_link`。`queued` 或只生成了预览文件不视为可点播已验证。

独立预览面板（包括 `open_in_codex`）、新窗口、浏览器和本机播放器仅在用户当次明确要求打开时启用。自动播放仅在用户当次明确要求播放时启用。

## 对比视频交付规则

原片居左，各版按约定顺序并排，每栏顶部标注版本名。用户点击播放后，各版画面同步。各版音轨可切换，默认选中原片音轨。对比视频与成片存放在同一文件夹。

## 视频背景替换的项目约定

- 用户要求保留人物、商品和动作时，先从原视频选择与实际动作对应的关键帧，再制作替换背景的参考帧；背景、手部、商品结构和穿戴状态分别核对。
- 用户授权时，可使用本机已有的 Qwen-Image-Edit-2511 生成或编辑关键帧，不因普通技术故障而重复询问已经给出的授权。先检查队列和模型，避免影响其他任务。
- 使用复刻爆款路线替换背景时，内置图片模型的关键帧补图按上方「视频复刻关键帧补图」执行。
- 参考帧与对应原片段一起用于视频制作。生成后按原片检查产品、动作、人物、背景和声音；关键帧一致不等于动态视频已验收。
- 需要新付费、扩大上传范围或超出已授权重试范围时，先说明具体范围并取得授权。确认通过后分别回拼完整视频，保留源文件。
