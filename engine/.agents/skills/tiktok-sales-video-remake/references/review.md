# 发布后复盘

优先用用户后台导出、截图或已授权的只读取数。补齐视频 ID、版本、商品/变体、站点、发布时间、时区、曝光或播放、商品点击、支付订单、可取得的留存和流量来源。记录指标定义、归因窗口、数据更新时间、退款处理及广告与自然流量范围。用同一统计规则对齐发布后观察时长，例如双方各自首 48 小时。现有数据有哪些就先用哪些，空白记为未取得。

1. **观看与留存**。对比播放量和可取得的同一时点留存、完播率或平均观看时长，查下降的位置是否对得上首帧、证据出现、重复段或 CTA。视频时长不同，注明比较的是固定秒点还是对应情节。
2. **商品点击**。用同口径商品点击和后台定义的分母。在只有播放量且两者计量范围一致时，可报告每百次播放的商品点击数，明确分母。商品曝光和视频播放分开记录。
3. **支付订单**。对照相同归因范围与窗口的点击和支付订单。拿到一致口径才比较订单率，记录分子、分母和样本数。遇到价格、促销、库存、流量、商品页或归因差异，把它们写进解释限制。各环节的数据无法对齐时，保留各自观察，不跨窗口算转化率。
4. **下一条只改一个变量**。给出观察、可能原因或反证、镜号和要换成的画面/台词/时点、要保留的条件、主指标与复测窗口。开头留存掉得早且证据出现晚，可先试换第一画面或提前证据中的一项。留存可比但商品点击落后，先查购买异议与购物入口再定位一项创意测试。点击与订单背离时先查商品页、库存和归因，避免把问题直接归到脚本。数据不足时把修改标为待验证假设，写下需要的具体字段。

交付一页，按「数据与口径 → 判断和限制 → 下一条的唯一改动 → 复测条件」写。用户要求开始新稿时，复用既定商品、版本和素材，直接把该变量落实到对应镜头。
